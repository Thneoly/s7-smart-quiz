## 0. 产品形态决策（桌面 vs Web）——先回答这个问题

**结论：讲师/机构桌面端（Tauri）先行，学员移动/Web 端列入 Roadmap，共用同一套核心引擎。**

| 论点 | 说明 |
|---|---|
| 为什么桌面先行 | ① 讲师组卷/批量管理/题库导入/打印是桌面强场景；② 培训机构内网离线考试是真实付费场景；③ 大题库本地管理（10万题级导入/去重/统计） |
| 桌面的代价（清醒认知） | SmartScreen 签名、更新通道、WebView2 依赖三座大山——本方案已逐项给出对策（§6/§8），但它们是真实成本 |
| 学员侧假设与验证 | 假设"碎片时间刷题主要在手机"成立度未知 → M1 阶段用现有 Web 练习平台加匿名计数（页面级，无个人信息）验证使用时段/设备分布，再决定 Web/PWA 优先级 |
| 复用保障 | 判分引擎/组卷引擎/SM-2/蓝图全部写成**纯 TS 无依赖模块**（`engine/`），桌面与未来 Web 端直接复用；数据 schema 与 SQLite 语义一致，Web 端可平移到 sql.js/wasm |

## 1. 项目定位与目标

### 1.1 产品定位
**本地优先（Local-first）、零遥测、可离线**的桌面题库与考试平台，后续可扩展云端同步。首发题库：S7-200 SMART 认证（种子数据：344 道知识点题 + 5 套模拟卷 350 题，含答案/解析/出处/置信度）。架构支持多题库分发（`.smartbank` 文件）。

### 1.2 目标用户
| 用户 | 场景 | 对应模块 |
|---|---|---|
| 备考学员 | 刷题、模考、错题复习、进度追踪 | 练习/考试/错题本/分析 |
| 培训机构讲师 | 组卷出题、导入自有题、班级学情报告、纸质考试 | 题库管理/打印/成绩合并 |
| 题库维护者 | 题目审核、按作答数据优化、题库版本发布 | 质量看板/审核队列/签名打包 |

### 1.3 核心价值
1. 离线可用 + 数据本地化（贴合工控培训现场）
2. 带解析与官方出处的**可信题库**（答案带置信度分级，低置信度不参与判分）
3. 数据驱动的题库优化闭环（个人 + 讲师班级两级）
4. 从刷题工具到学情分析（能力雷达、薄弱知识点、趋势）

## 2. 总体架构

### 2.1 架构图

```
┌───────────────────────────────────────────────────────────┐
│ Tauri 2 桌面壳（Rust core，Windows x64 首发）              │
│ ┌─────────────────────────────────────────────────────┐   │
│ │ WebView 前端（Vue 3 + TS + Vite + Naive UI + ECharts）│   │
│ │ engine/（纯TS：grader/session/srs/blueprint/dedupe） │   │
│ └──────────────┬──────────────────────────────────────┘   │
│                │ invoke（async commands，JSON IPC）         │
│ ┌──────────────▼──────────────────────────────────────┐   │
│ │ Rust 服务层（薄后端）                                 │   │
│ │ bank（导入/版本/去重） exam（会话/成绩重算）           │   │
│ │ stats（P/D 批量重算） export（xlsx/docx/pdf）          │   │
│ │ backup（VACUUM INTO） bankasset://（自定义协议）       │   │
│ │ updater（tauri-plugin-updater + minisign）            │   │
│ └──────────────┬──────────────────────────────────────┘   │
│ ┌──────────────▼──────────────────────────────────────┐   │
│ │ SQLite（rusqlite，WAL）：bank.db ｜ user.db            │   │
│ └─────────────────────────────────────────────────────┘   │
└───────────────────────────────────────────────────────────┘
资源：resources/seed/*.smartbank（首启导入）  AppData/banks/（用户题库）
```

### 2.2 关键架构决策

| 决策 | 选择 | 理由与要点 |
|---|---|---|
| 桌面框架 | **Tauri 2** | 体积小、内存低；**代价已识别**：WebView2 依赖（§6 分发矩阵）、签名与更新链路（§8 发布就绪）。备选 Electron 仅当团队 Rust 完全不可行时启用 |
| 前端 | Vue 3 + TS + Vite + Naive UI | TS 友好/暗色一流/可离线打包；engine 纯 TS 便于未来 Web 复用 |
| 存储 | **rusqlite（bundled）** | 同步 API 简单可靠；**所有 command 标 `async` + 长任务 `spawn_blocking`**，连接用 `Mutex<Connection>`；~~sqlx/tauri-plugin-sql 退路已删除~~（前者引入异步栈复杂度，后者把 SQL 拼接收敛回前端，与本架构的信任边界冲突） |
| 判分 | 前端 TS 即时反馈 + **交卷时 Rust 按答案与计分规则重算入库** | 对外可信成绩的信任边界；防前端引擎改版后历史口径漂移 |
| 图片加载 | **自定义 `bankasset://` 协议**（`register_uri_scheme_protocol`） | 按 `bankasset://<bank_id>/<相对路径>` 统一解析：内置（resources）/ 导入（AppData）/ 打包题库一套逻辑通吃；CSP `img-src` 加该协议。~~asset:// 直写方案废弃~~（需 convertFileSrc + 双 scope，且不适配付费题库单文件） |
| 中文搜索 | **jieba-rs 写入时预分词** → FTS5 建在 `*_seg` 列；查询词同过 jieba | FTS5 默认分词器对中文不可用（整句单 token）。备选 trigram（有 3 字下限，2 字高频词需 LIKE 兜底）。**M0 做 spike 验证**；344 题规模 LIKE 即可，FTS 推迟 M2+ |
| 打包 | NSIS 双渠道 + zip（附属） | 见 §6 分发矩阵 |
| 更新 | tauri-plugin-updater：**全量安装包 + minisign 签名**（~~差分包~~不存在此能力） | 密钥对生成与保管（私钥进 CI secret，丢失=历史用户无法升级）是 M3 硬任务；zip 渠道手动更新 |

### 2.3 题库解耦与存储拓扑（评审后定稿）
- **种子题库**以 `.smartbank` 文件打进 `resources/seed/`；**首次启动导入（复制）**到 AppData 下可写 `bank.db`，标记 `is_builtin=1`（禁止用户改题，保留"内置只读"语义）
- 应用升级携带新版本种子 → 按 `bank.version` **diff 幂等刷新**内置题（用户对内置题的笔记/记录不受影响）
- 第三方/付费题库同样是 `.smartbank` 文件导入落库（含资产 zip 解包到 `AppData/banks/<bank_id>/assets/`）
- 单一可写库：所有 CRUD、FTS 索引、去重合并都发生在一个 bank.db 上（~~ATTACH 只读库方案废弃~~：跨库事务/触发器/FTS 复杂且 is_enabled 无处安放）

## 3. 数据模型（SQLite）

### 3.1 题库库 `bank.db`（AppData 下可写；复合主键全链路统一）

```sql
CREATE TABLE banks (
  bank_id     TEXT PRIMARY KEY,          -- 'smart-core' / uuid
  name        TEXT NOT NULL,
  version     INTEGER NOT NULL,          -- 题库内容版本（diff 刷新依据）
  schema_ver  INTEGER NOT NULL,          -- .smartbank 格式版本
  description TEXT,
  is_builtin  INTEGER DEFAULT 0,
  is_enabled  INTEGER DEFAULT 1,
  asset_root  TEXT,                      -- 资产目录绝对路径（导入时落定）
  imported_at TEXT
);

CREATE TABLE topics (
  topic_id INTEGER PRIMARY KEY,
  bank_id  TEXT NOT NULL,
  parent_id INTEGER,
  name     TEXT NOT NULL,
  sort_order INTEGER,
  FOREIGN KEY (bank_id) REFERENCES banks(bank_id)
);

CREATE TABLE questions (
  bank_id     TEXT NOT NULL,
  qid         TEXT NOT NULL,             -- bank内唯一；导入生成规范：默认 "<bank前缀>-<uuid8>"，防人工撞号
  version     INTEGER NOT NULL DEFAULT 1,-- 题目内容版本（改题+1；统计按版本聚合）
  type        TEXT NOT NULL CHECK(type IN ('single','multi','judge','fill')),
  stem        TEXT NOT NULL,             -- Markdown
  img_path    TEXT,                      -- bank 资产目录内相对路径
  options     TEXT NOT NULL,             -- JSON 数组
  answer      TEXT NOT NULL,
  answer_conf TEXT DEFAULT 'high',       -- high/medium/low（种子数据AI置信度）
  explain     TEXT,
  source      TEXT,
  difficulty  INTEGER DEFAULT 3,
  status      TEXT DEFAULT 'active' CHECK(status IN ('active','retired','pending_review')),
  created_at TEXT, updated_at TEXT,
  PRIMARY KEY (bank_id, qid),
  FOREIGN KEY (bank_id) REFERENCES banks(bank_id)
);
CREATE INDEX idx_q_status ON questions(bank_id, status, type);   -- 组卷候选池

CREATE TABLE question_topics (
  bank_id TEXT NOT NULL, qid TEXT NOT NULL, topic_id INTEGER NOT NULL,
  PRIMARY KEY (bank_id, qid, topic_id),
  FOREIGN KEY (bank_id, qid) REFERENCES questions(bank_id, qid)
);
CREATE INDEX idx_qt_topic ON question_topics(topic_id);          -- 章节抽题反向查

CREATE TABLE papers (
  paper_id  INTEGER PRIMARY KEY,
  bank_id   TEXT NOT NULL,              -- NOT NULL：卷必属某库
  name TEXT NOT NULL, source_url TEXT, description TEXT, is_builtin INTEGER DEFAULT 0,
  FOREIGN KEY (bank_id) REFERENCES banks(bank_id)
);
CREATE TABLE paper_questions (
  paper_id INTEGER NOT NULL, bank_id TEXT NOT NULL, qid TEXT NOT NULL,
  sort_no INTEGER, score REAL DEFAULT 1,
  PRIMARY KEY (paper_id, bank_id, qid),
  FOREIGN KEY (bank_id, qid) REFERENCES questions(bank_id, qid)
);

-- 全文搜索（M2+，M0 仅 spike）：jieba-rs 预分词列
CREATE VIRTUAL TABLE questions_fts USING fts5(
  stem_seg, options_seg, explain_seg,
  content=''                             -- contentless，按 (bank_id,qid) rowid 映射表关联
);
CREATE TABLE fts_map(rowid_alias INTEGER PRIMARY KEY, bank_id TEXT, qid TEXT);

-- 改题/并题追溯（保持 answer_records 只追加）
CREATE TABLE qid_mapping (             -- 并题/迁移映射：旧题统计 join 此表
  old_bank TEXT, old_qid TEXT, new_bank TEXT, new_qid TEXT,
  mapped_at TEXT, PRIMARY KEY (old_bank, old_qid)
);
```

### 3.2 用户数据库 `user.db`

```sql
CREATE TABLE sessions (
  session_id  INTEGER PRIMARY KEY,
  mode        TEXT NOT NULL,             -- practice/exam/mock/wrong/fav/recite
  title       TEXT, bank_id TEXT, paper_id INTEGER,
  blueprint   TEXT,                      -- 组卷蓝图 JSON（考试模式）
  total_qty INTEGER, scored_qty INTEGER,
  correct_qty INTEGER, score REAL,
  duration_ms INTEGER,
  started_at TEXT, finished_at TEXT,
  qid_list    TEXT,                      -- 会话题目有序列表 JSON：[["smart-core","T001"],...]（瘦身后快照）
  bank_version INTEGER                   -- 组卷时题库版本；题目后续被改/退役时按需落个别快照
);
CREATE INDEX idx_sess_time ON sessions(finished_at);

CREATE TABLE answer_records (            -- 只追加，永不 UPDATE
  record_id   INTEGER PRIMARY KEY,
  bank_id TEXT NOT NULL, qid TEXT NOT NULL, q_version INTEGER NOT NULL,
  session_id  INTEGER NOT NULL,
  picked      TEXT,
  is_correct  INTEGER,                   -- 0/1/null（无答案/低置信度）
  time_cost_ms INTEGER, answered_at TEXT NOT NULL,
  FOREIGN KEY (session_id) REFERENCES sessions(session_id)
);
CREATE INDEX idx_ar_question ON answer_records(bank_id, qid);   -- 统计聚合键（必须有，防二次方退化）
CREATE INDEX idx_ar_session ON answer_records(session_id);
CREATE INDEX idx_ar_time ON answer_records(answered_at);

CREATE TABLE wrong_book (
  bank_id TEXT, qid TEXT,
  wrong_count INTEGER DEFAULT 1, last_wrong_at TEXT,
  PRIMARY KEY (bank_id, qid)
);   -- "消灭"不再独立计数，统一读 review_queue.repetitions（单一调度源，见 §4.4）

CREATE TABLE review_queue (              -- SM-2（修正版状态机，见 §4.2）
  bank_id TEXT, qid TEXT,
  ease REAL DEFAULT 2.5, interval_days REAL DEFAULT 0,
  repetitions INTEGER DEFAULT 0, due_date TEXT,
  PRIMARY KEY (bank_id, qid)
);

CREATE TABLE favorites (bank_id TEXT, qid TEXT, created_at TEXT, PRIMARY KEY (bank_id, qid));

CREATE TABLE notes (                     -- 题目笔记（评审新增）
  bank_id TEXT, qid TEXT, content TEXT, updated_at TEXT,
  PRIMARY KEY (bank_id, qid)
);

CREATE TABLE question_stats (            -- 讲师/维护者视角；个人正确率不落此表
  bank_id TEXT, qid TEXT, q_version INTEGER,
  n INTEGER, p REAL,                     -- 难度系数=正确率
  d REAL,                                -- 区分度（按会话得分27%分组）
  high_p REAL, low_p REAL,
  option_dist TEXT,                      -- JSON 选项选择分布
  computed_at TEXT,
  PRIMARY KEY (bank_id, qid, q_version)
);

CREATE TABLE settings (key TEXT PRIMARY KEY, value TEXT);
```

**快照策略（评审修订）**：考试会话只存 `qid_list` + `bank_version`（≈1KB/卷 vs 原 130KB）；回顾时按需读 bank.db，若题目 version 已变/已退役则**仅对该题**落快照到 `sessions.qid_list` 同行 JSON 扩展字段；练习会话不存题面；`answer_records` 永久保留。

**备份**：`VACUUM INTO` 或 rusqlite backup API 生成一致性快照（WAL 下直接拷文件会丢已提交事务/拷出撕裂帧）；备份 manifest 记录 `schema_version` + 已启用题库的 bank_id/version/SHA256；恢复时先 migrate 再替换（关闭写连接后进行）。

### 3.3 数据流
`前端判分(即时反馈) → invoke 异步批量写 answer_records（会话缓冲，30s/切题时 flush）→ 交卷时 Rust 重算成绩并写 sessions 汇总（由 answer_records 一条 SQL 聚合，不逐题累加）→ 会话结束时批量重算 review_queue / 讲师题库的 question_stats（按会话粒度，因区分度需会话总分）→ 断点续考草稿（当前 picks/标记/剩余时间）独立 draft 存储节流落盘`

## 4. 功能模块详细设计

### 4.1 考试模式（Exam）

**组卷方式**
1. **固定卷**：A~E 卷 / 讲师导入卷
2. **蓝图组卷**（规格化，算法修复）：
```json
{
  "name": "全真模拟", "time_limit_min": 90, "pass_line": 60,
  "multi_score_policy": "all_or_nothing",
  "sections": [
    {"type":"single","qty":40,"score_each":1,"from_topics":["*"],"difficulty":null},
    {"type":"multi","qty":30,"score_each":1,"from_topics":[12,15],"difficulty":[3,5],"topic_scope":"subtree"}
  ]
}
```
**组卷算法**：① 先按 `(bank_id, type, difficulty, status='active', topic子树)` 计数校验候选池 ≥ qty；不足按蓝图声明的降级策略（放宽难度→减题量→明确报错，禁止静默缺题）② 逐 section 随机采样（`ORDER BY random() LIMIT n` 走候选索引；10 万题级改 rowid 采样）③ 跨 section 去重（临时表 NOT EXISTS）④ from_topics 用 topic_id，默认子树语义。

**考试进行**：倒计时（到点自动交卷）、答题卡、疑问题标记、防误退、**断点续考**（30s 草稿落盘，重启恢复倒计时与已答）、可选全屏专注模式。

**成绩单**：总分/用时/章节得分率雷达/历史趋势；多选计分策略可配（**默认全对才得分**，可选漏选得半）；逐题回顾（所选 vs 正确 + 解析 + 出处 + 置信度标注）；导出 PDF/Excel；`answer_conf=low` 或无答案的题**排除出分母并显著标注**。模考参照（M2 后增强）：题库更新包内嵌离线分位数 → "超过 xx% 使用者"。

### 4.2 练习模式（Practice）

| 子模式 | 行为 |
|---|---|
| 章节练习 | 知识点树选择，顺序刷题，即时判分 |
| 随机练习 | 数量/题型/难度抽题 |
| 背诵模式 | 题干→答案→解析直接翻看 |
| 间隔重复复习 | review_queue 到期题（SM-2） |
| 错题重练 | 错题本成卷；消灭判据 = review_queue.repetitions≥2 |
| 收藏练习 | 收藏夹成卷 |

**SM-2 状态机（修正版，srs.ts 首要单测用例）**：
```
答对: repetitions=1 → interval=1天；repetitions=2 → interval=6天；
      以后 interval = interval × ease（ease 可选答"艰难"时 -0.2，下限1.3）
答错: repetitions=0, interval=1天, due=now+1天
due_date = now + interval
```
**计入规则（与错题本统一）**：仅练习/复习/错题重练模式驱动 SM-2 与消灭计数；**考试/模考只采集不驱动状态机**（防"考试里碰巧做对"污染）；同题最小重投间隔 ≥1 天（防当天连刷凑满连击）。

### 4.3 记录与学情分析
- 会话历史（任意一次逐题明细回看）、总览仪表盘（打卡热力图/趋势/连续天数）
- 知识点正确率树着色下钻；十大主题能力雷达
- **个人**正确率即学情主口径（本地单机数据的正确用法）
- 讲师班级侧（M3）：**多用户档案绑定姓名/学号** → 成绩导出携带学员标识 → 讲师端"导入多份成绩 → 班级学情报告"（平均分/知识点通过率/未通过名单）
- 导出：成绩单 PDF、明细 Excel

### 4.4 错题本
自动收集（考试也收集但不驱动消灭）；筛选（章节/错误次数/未消灭）；**消灭 = SM-2 repetitions≥2**（单一调度源，UI 同步隐藏"复习到期"）；错题+笔记导出 PDF；退役题置灰标注可清理。

### 4.5 题库管理与优化

**导入**：`.smartbank`（标准：元信息+题目+资产 zip+SHA256+[可选]ed25519 签名+license 字段预留）/ Excel / Markdown / 问卷星 JSON。
**Excel 模板规范（M3 前定稿并内置下载）**：章节用 `一级章节/二级章节` 两列、多知识点分号分隔；图片用独立文件夹+`图片文件名`列关联（导入向导打包）；题型枚举与中文标头映射表；答案归一化（判断题 对/错/√/× → T/F；多选 `ABD`/`A,B,D` 容错）；填空题多空用 `||` 分隔、判分=全对或包含（蓝图声明）。
**去重**：归一化题干精确一致 → 疑似重复；SimHash 海明距离 ≤3 → 相似；合并走 `qid_mapping`（统计 join 映射，不改写明细）。
**质量分析（口径修正）**：
- **个人层面**：正确率/耗时/错误分布（始终可用）
- **题库层面 P/D/选项分析**：仅当存在跨用户数据时有效 → 默认基于**讲师班级合并数据**计算；评级条件：`n≥150 且高低分组各≥20` 才判区分度；选项分析 `n≥100 且选择率<5%` 提示更换干扰项（原 n≥30/5% 阈值在统计上为噪声：SE(p)≈0.18，SE(D)≈±0.25）
- 重算时机：会话结束批量并入 / 每日低频全量 / 手动；不逐条触发
**审核流**：`pending_review` 队列（含种子库 AI 低置信度答案题——导入即入队，人工确认前**不参与判分**）→ 改题 version+1 / 退役；批量操作（多选改章节/难度/状态/退役/重绑知识点）。
**版本与分发**：题库版本 diff 升级；`.smartbank` 签名打包工具（随 M3 交付）。

### 4.6 通用功能
深浅色/字号/快捷键；**题目笔记**（做题页+回顾页可写可看，随错题导出）；分享卡片（生成图片，M2 后）；多用户档案（学员/讲师角色视图）；数据备份恢复（§3.2）；FTS 搜索（M2+）；**纸质试卷打印**（M3 讲师包：A4 双栏/密封线/大题头与分值/页眉（卷名·总分·时长）/**独立答题卡页**（涂卡网格与 paper_questions 顺序映射）；技术路线 docx 模板优先、PDF 由模板生成，讲师可二次编辑）。
