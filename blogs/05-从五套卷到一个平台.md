# 从 5 套卷到一个 9.5MB 的桌面平台：一个备考工具的完整诞生记

> **TL;DR**：一个"整理几套在线试卷"的半小时需求，一步步长成了一个可对外发布的本地优先题库平台：官方文档 → AI 出题+校验 → 694 题可信题库 → Tauri 桌面应用（学习指南/练习/考试/错题本/资料速查/全文检索/导入/打印/自动更新）。这篇不抠技术细节，讲**每一步扩张背后的触发条件**、贯穿全局的架构决策，以及诚实的复盘。

## 一、需求演进线

```
整理 5 套在线模拟卷（半小时的活）
  → 卷子没有答案，得从官方文档整理      → 提取 CHM/PDF（2000+ 页）
  → 文档读不过来，让 AI 出题+校验       → 344 题题库 + 350 题答案
  → 刷题得有工具                       → 离线练习平台
  → 要正式对外，得是桌面应用            → Tauri 方案（三视角评审后定稿）
  → M0 骨架（种子导入 / FTS spike / 图片协议）
  → M1 MVP（练习六模式 / 考试 / SM-2 错题本 / 断点续考）
  → M2（蓝图组卷 / 导出 / 备份 / 设置 / 协议合规）
  → M3（资料速查+全文检索 / Excel 导入 / 去重 / 打印 / 自动更新）
```

回头看，每一步扩张都有明确的触发条件（"没答案没法用""网页版没法正式分发"），没有一步是提前规划大而全。**但架构上始终为扩张留门**：数据从第一天就是结构化的（JSON/SQLite schema 先行），所以每一步都是加楼，没有推倒重来过。

对比另一种路径——第一天就设计"全功能平台"——大概率死在第一周：为一个假想的未来过度设计，而真实的下一步需求（比如"答案要带置信度"）反而没留位置。

## 二、产品最终长什么样

一个 Windows 桌面应用，8 个主功能：

| 模块 | 内容 |
|---|---|
| 📖 学习指南 | 官方 22 章课程的结构化路径：学习目标/核心要点/课时/优先级/配套练习直达，进度追踪 |
| 📚 练习 | 章节/随机/背诵/SM-2 间隔复习/错题重练/收藏，即时判分带资料出处 |
| 📝 考试 | 5 套真题（计时/答题卡/断点续考）+ 蓝图组卷（题型×主题×难度，候选不足自动降级） |
| ❌ 错题本 | 连对 2 次消灭（单一调度源），下次复习时间可见 |
| 📈 学情 | 15 周热力图/主题正确率/趋势/全部历史回看 |
| 📇 资料速查 | 211 条结构化数据：12 款 CPU 全参数对比、91 张指令卡、通信/故障/公式速查 |
| 🔍 全文检索 | 962 个官方文档，jieba×FTS5，0.4ms 级，每条结果带出处 |
| 🛠 管理 | Excel 题库导入（校验预览）、SimHash 去重合并、A4 试卷打印+答题卡、minisign 自动更新 |

## 三、几个贯穿全局的决策

**1. 本地优先 + 零遥测。** 目标用户是工控培训场景（弱网/内网/隐私敏感），所以数据全在本地、无任何上报，"诊断包"是用户手动导出的 zip。这不是技术妥协，是产品定位——它反过来约束了功能设计：AI 答疑这类必须联网的功能，方案里明确为"用户自带 API Key + 默认关闭"，与首启协议里的零遥测承诺自洽。**隐私承诺是一张网，签了之后每个新功能都要过一遍这张网。**

**2. 权威逻辑只有一份。** 判分、SM-2、组卷全部实现在 Rust（交卷时重算入库），前端只做展示反馈。同一段逻辑写两份（TS 一份 Rust 一份）必然漂移——成绩是可能给讲师看的东西，不能由前端说了算。

**3. 置信度是产品逻辑，不是标注装饰。** AI 整理的答案分 high/medium/low：low 不参与判分（用户看到"答案整理中"，比看到错答案好得多）、medium 进人工复审队列。AI 产物必须带着"我有多确定"的元数据在系统里流转。

**4. 每个里程碑以测试收口。** cargo 集成测试 11 项 + Playwright E2E 47 项，每次加功能全量回归。E2E 抓过草稿丢失时序 bug、答题卡状态 bug——这类问题手动测试永远测不全。**测试不是质量部门，是"敢继续往上盖楼"的地基。**

**5. AI 是流水线上的工种。** 全程 50+ 个代理：出题工 10 个、校验工+答案工 15 个、评审工 3 个、指南整理 3 个、资料员 7 个……各有各的提示词（岗位说明书）和考核标准（schema+出处+证据要求）。人负责定规格、拆任务、验收、拍板。

## 四、如果重来会改什么

1. **更早写数据迁移框架。** schema 改过三次（settings 表后加、复合键、docs 索引表），全靠 `CREATE TABLE IF NOT EXISTS` 硬扛。第 100 个用户时必须有版本化 migrate
2. **发布合规更早启动。** 代码签名证书周期数周，应该 M1 就申请，而不是 M2 才写进 checklist
3. **工作流产物第一天就文件化。** 依赖执行框架的 journal 缓存吃过两次亏（429 崩流、落盘丢失），后来所有代理直接写目标文件才稳

## 六、适合谁、怎么用

- **备考西门子初级认证的工程师**：学习指南划重点 → 章节练习 → 真题模考 → 错题消灭，全程离线
- **培训机构讲师**：Excel 导入自有题库、蓝图组卷出卷、A4 打印带答题卡线下考试、成绩 Excel 导出
- **想做类似工具的开发者**：整套资料（结构化数据 schema、多智能体流程、评审方法）都可以参考本系列其余三篇

## 七、写在最后

这个项目最有趣的不是某个技术点，而是**一条"内容工程"的完整链路**：非结构化的官方文档（CHM/PDF）→ AI 流水线（出题/校验/评审）→ 带置信度与出处的结构化数据 → 装进一个尊重用户（本地优先/零遥测）的产品形态。

每一步都不复杂，难的是每一步都把"可信"往前推一格：出处字段、对抗校验、置信度分级、单一权威逻辑、测试收口。**工具链是 Python + Rust/Tauri + Vue3 + Playwright + 多智能体，朴素得不能再朴素——朴素的东西组合到位，就是生产力。**

系列前三篇是技术细节：多智能体题库生成、Tauri 2 踩坑实录、对抗式设计评审。有具体问题欢迎交流。
