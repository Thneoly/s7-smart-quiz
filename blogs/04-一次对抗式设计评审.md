# 一次对抗式设计评审：三个"杠精"视角如何救了一个项目

> **TL;DR**：写完 40 多页的技术方案后，我没有直接开工，而是派了三个 AI 代理从不同视角攻击它。产出：3 个 blocker、15 个 major、7 个 minor——包括"分发方式与目标用户自相矛盾""主键设计晚改等于双库迁移""WAL 备份丢数据""统计阈值在数学上不成立"这类返工级问题。这篇讲具体做法、提示词设计和最有价值的发现。

## 〇、为什么方案也需要"对抗"

AI 辅助开发最常见的翻车路径：方案写得头头是道 → 顺利开工 → 第三个里程碑发现数据模型返工。

方案阶段的问题**修改成本最低**——改一行 schema 设计 vs 已发布用户数据迁移。但自查有天然盲区：写方案的人和检查方案的是同一个脑子，有同样的知识盲区和同样的"这里应该没问题吧"。

解法很直接：**用多个独立上下文的模型实例，给不同的"杠精"人设，要求只报真问题、按严重度分级、给出证据**。

## 一、评审的搭建

三个视角，各自一个独立代理，上下文互不可见：

| 视角 | 人设与关注点 |
|---|---|
| **技术可行性** | 框架的真实约束（不是宣传语）、依赖链、里程碑人力是否现实 |
| **产品完整性** | 对标成熟竞品找功能缺口、分发链路（签名/更新/反馈）、商业闭环 |
| **数据与算法** | 逐表核对 schema、算法规格的数学正确性、统计阈值的统计学意义 |

提示词里有四个关键设计：

1. **先读全文再评**：评审对象是 40 页方案原文，不喂摘要——细节问题都藏在细节里
2. **分级强制**：`blocker`（导致返工/无法上线）、`major`（明显欠缺）、`minor`（改进项）。没有分级的评审会输出一堆正确但无用的废话
3. **证据要求**：blocker 必须说明返工路径，判错必须引用原文——过滤掉感觉式批评
4. **反凑数条款**：明写"只报告真实、具体、可执行的问题，不要为了凑数报无关痛痒的小节"

输出用 JSON schema 强约束，便于汇总追踪：

```json
{
  "issues": [
    {"severity": "blocker", "section": "2.2 打包",
     "issue": "免安装zip在无WebView2机器上白屏退出，与'工控现场弱网'目标用户矛盾",
     "suggestion": "双渠道分发矩阵+启动显式探测"}
  ],
  "overall": "总体评价一两句"
}
```

## 二、评审抓到的返工级问题（节选）

**1. 分发与场景自相矛盾（blocker）**
方案一边承诺"免安装 zip + 10MB 体积"，一边目标用户写着"工控现场、弱网环境"。而免安装 zip 在没有 WebView2 的机器上**直接白屏退出**——这类机器恰恰常见于工控现场；NSIS 默认的 downloadBootstrapper 又需要联网。修正为双渠道分发矩阵 + 启动显式探测。写方案时每一段都"局部正确"，拼起来才矛盾——**这正是自查发现不了的**。

**2. 主键设计与核心卖点冲突（blocker）**
`questions.qid` 单列主键，但产品核心规划是"多题库/付费题库"。第二个题库出现同号 qid（Excel 导入自动编号极易撞）时导入直接主键冲突。开发到 M3 才发现的话 = 已发布用户双库数据迁移。修正：全链路复合键 `(bank_id, qid)`。

**3. WAL 下备份丢数据（blocker）**
"一键备份 user.db"按字面实现：只拷主文件丢 -wal 里已提交事务（最近一次考试记录静默消失）；不持锁连 -wal 一起拷可能拷出撕裂帧。修正：`VACUUM INTO` 一致性快照。

**4. SM-2 的零间隔死锁（major）**
简化版 SM-2 写"答对间隔×ease"，interval 初值 0——**0×2.5=0，题目永远进不了到期队列**。上线后的表现是"复习功能使用率为零"，极难定位。正解是标准状态机（rep1→1天、rep2→6天、之后×ease），并写成第一个单元测试。

**5. 统计阈值在数学上不成立（major）**
题库质量分析写了"n≥30 判区分度 D"。评审算账：n=30 时 D 的噪声约 ±0.25，**大于 0.2 的判定阈值——评级基本是随机数**；选项分析 5% 阈值在 n=30 时等于"少于 1.5 人选择"。修正：D 判定需 n≥150 且高低分组各≥20，选项分析 n≥100。人写阈值时很少算标准误，这是"数据与算法"视角的独有贡献。

**6. 两套状态机打架（major）**
错题本"连对 2 次消灭"和间隔重复 SM-2 是两套独立状态机，同一次作答同时驱动两者：考试里碰巧做对算不算消灭计数？当天错题重练连做两遍算不算连击？消灭后复习队列还排不排？修正：单一调度源（消灭=repetitions≥2）+ 计入模式白名单（考试只采集不驱动）+ 同题最小重投间隔。

**7. 商业闭环是坏的（blocker）**
"付费题库=分发一个 ed25519 签名文件"——签名解决完整性和作者身份，**不解决授权**：购买者把签名合法的文件拷给任何人都能导入。要么明说"不防盗版、收入靠版本服务与机构授权"，要么把离线授权（机器指纹+激活码换 license）排进里程碑。拖到收费那天再改 = 文件格式、校验逻辑、已流出副本三头返工。

还有一批"看似开箱即用、实则需要专项设计"的：FTS5 中文分词（默认分词器对中文不可用）、`asset://` 图片协议（scope 配置与付费题库单文件分发冲突）、Windows Authenticode 代码签名（OV 证书周期数周，必须 M1 就启动采购——否则 M2 "对外发布 Beta"当天被 SmartScreen 拦截）。

## 三、成本、收益与闭环

成本：三个高推理度代理读 40 页方案，几分钟出报告。
收益：第 2、3、4 条任何一条漏到开发期都是**数天级返工**；第 1、7 条漏到发布是**口碑与收入级损失**。

最重要的一步是**闭环**：25 条意见逐条落进方案 V1.1 修订版，并附修订日志（哪条评审意见→改了哪一节）。评审不闭环等于没做——三周后没人记得"当时为什么这么改"。

这个模式后来贯穿了整个项目：

```
出题（10代理） → 对抗校验（15代理逐题核原文，抓到 PID 8→16 版本冲突）
方案 V1.0    → 三视角评审 → V1.1（开发基线）
```

## 四、你可以直接抄的评审提示词骨架

```
你是<领域>审校专家。先完整阅读<方案/产物全文>。
背景：<项目上下文、团队规模、已有资产>。
你的任务是挑毛病：只报告真实、具体、可执行的问题。
severity：blocker=导致返工/无法上线；major=明显欠缺；minor=改进项。
要求：blocker 说明返工路径；判错引用原文；不要为凑数报告无关痛痒的小节。
按 schema 输出 {issues:[{severity,section,issue,suggestion}], overall}。
```

三个成败细节：**全文输入**（不要摘要）、**独立上下文**（三个实例互相看不见）、**证据与分级**（不然得到的是一堆正确的废话）。

## 五、写在最后

AI 时代最被低估的用法，可能不是"帮你写"，而是**"用一个没有沉没成本偏见的实例，攻击你刚写完的东西"**。

人对自己的方案有沉没成本——写到第 40 页时，已经不想承认第 2 页的假设有问题。AI 评审者没有这个问题：它第一次读这份方案，没有"我当时为什么这么写"的情感包袱，只有"这一段和那一段矛盾"的事实判断。配上分级和证据要求，它就是那个最好的杠精同事。
